Tuning

Less input lag and steadier frames, done from inside the game and at launch. Measured, not promised: every switch shows its effect below, and the before/after test runs both on the same game.

Reading the machine…

Inside the game

Render queue

Just in time holds the game after each frame so its next one is built as late as possible and never waits in Present: the input is that much fresher and the GPU never idles. Measured on a GPU-bound control: up to a frame less latency at the same frame rate, and nothing at all when the CPU is the bottleneck. Ultra goes further — no frame in flight — but costs frame rate whenever the CPU has work of its own.

auto follows the display

Held a few frames under the refresh rate, a variable-refresh display stays in range and the V-Sync queue never fills. The wait happens just before the frame goes out, so it is the newest one possible.

What this can and cannot do

  • Direct3D 11 and 12 games, through Present and Present1. Vulkan and OpenGL games are not seen: nothing here changes them and nothing is measured.
  • Games Librarian leaves alone for the achievement overlay (hypervisor releases) are left alone here too.
  • If the DLL hits a fault it switches itself off for that session; the game keeps running. The status line above says so.
  • Changes to the display rate and power plan are undone when the last tuned game exits.
