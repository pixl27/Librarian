# Hook map — the Store

Scope: `#page-store` (search hero, recent chips, What's new button, search status,
results, front page, store detail page) plus the three dialogs the Store opens in
the shared modal (CS.RIN.RU picker, CS.RIN.RU folder choice, What's new).

Sources read: `src/index.html` 291-410 and 1176-1185 (modal shell),
`src/js/store.js` (whole), `src/js/app.js` 3578-4002, 4039-4802, 6364-6516
(modal), 497-583 (art helpers), 5556-5571 (tweenNumber), 6755-6765 (withBusy),
`src/js/kinetic.js` (whole), `src/js/dialogs.js` (whole), `src/js/trailer.js`
(whole), `src/js/enhance.js` 1033-1048 (spatial nav), `src/core/storeFront.js`,
`src/core/steamApi.js` 135-249, `src/core/newsFeed.js` (field names only).
Legacy CSS consulted for structure only: `design/legacy-ui/styles/store.css`,
`enhance.css` 2555-2950, `kinetic.css`, `main.css` 2535-2804.

Legend:
- **[S]** static markup in `src/index.html`
- **[G]** generated by JS (file:line of the template)
- `→` "JS writes"; `⇄` "JS toggles"
- Every class/id below is spelled exactly as in the code. Inline `style` values are
  quoted as written.

| Face | JS hides/shows it? | CSS must hide it when… |
|---|---|---|
| `#store-hero` | never | `[data-mode="detail"]` (legacy store.css:24). Folds to a bar when `[data-front="on"]` (store.css:39-75). |
| `#search-status` | never | `[data-mode="detail"]`. Legacy also `:empty { display:none }` when `[data-front="on"]` (store.css:66). |
| `#search-results` | never | `[data-mode="detail"]`. Legacy `:empty { display:none }` when `[data-front="on"]` (store.css:67). |
| `#store-front` | ⇄ `.hidden`: shown iff `data-mode="hero"` (store.js:619-625, MutationObserver store.js:665-670, and on `librarian:page` store.js:655-659) | Legacy also `[data-mode="results"] > #store-front { display:none }` and the detail rule (belt and braces). |
| `#store-detail` | ⇄ `.hidden`: removed in `open()` store.js:181, added in `close()` store.js:385 | — |

So the detail page and the results never coexist visually only because of CSS:
**`#page-store[data-mode="detail"] > :is(#store-hero, #search-status, #search-results, #store-front) { display: none; }` is load-bearing.**

Layout the JS assumes: legacy makes `#page-store.active` a flex column with
`overflow: hidden` (enhance.css:2558-2559) and lets each face scroll itself:
`#search-results` (`overflow-y:auto`, enhance.css:2773-2775), `#store-front`
(store.css:81-87), `#sd-scroll` (store.css:366-372). JS resets `#sd-scroll.scrollTop = 0`
on every open (store.js:183), so `#sd-scroll` must be the scroll container of the
detail face.

Keyboard: while `#store-detail` is open, a capturing `keydown` on `window` closes it on
Escape unless `#modal-overlay:not(.hidden), #palette:not(.hidden), #plan:not(.hidden), #lightbox:not(.hidden)` matches (store.js:391-401). Those overlays must keep using `.hidden`.

Events: leaving the Store page (`librarian:page` with another page) closes the detail
page (store.js:655-657).

States:

| Element | Hook | Written by | Meaning |
|---|---|---|---|
| `#store-hero` | ⇄ `.busy` | app.js:3594 (`setBusy`), on at 3740, off at 3749/3754 | A search request is in flight. Legacy swaps `.ico-glass` out and spins `.ico-ring` (enhance.css:2696-2697). |
| `#store-search-box` | ⇄ `.filled` | app.js:3838 (`syncField`), removed 3848 | Field has text → show `#store-search-clear` and `#store-search-kbd` (legacy hides both otherwise: opacity 0, pointer-events none). |
| `#store-search-box` | `.typing` (replayed) | app.js:3842 via `replay()` app.js:3597-3602 | Every keystroke: remove class, read `offsetWidth`, add class → restarts a one-shot pulse. **The class is never removed afterwards.** |
| `#store-search-box` | `.shake` (replayed) | app.js:3768 (no results), 3861 (query < 2 chars) | One-shot shake, same replay trick, never removed. |
| `#search-input` | `disabled` attribute | app.js:3743 on, 3751/3755 off | Disabled while searching. |
| `#store-sub` | → textContent | app.js:3989 | `Search ${label} by name or AppID.` where label = `Hubcap and Steam` / `Steam` / `Hubcap`; or `No manifest source is set up yet.` |

Animation note: because `.typing` and `.shake` stay on the element, both can be present
at once. Whichever rule comes later in the cascade owns `animation`; in the legacy order
(`.typing` then `.shake`) a box that has shaken once never pulses again on typing.
The replay mechanism only needs each class to carry its own `animation-name`; avoid
transitions that key off the class being added (it is already present).

Behaviour: Enter with ≥ 2 chars runs the search; Escape with text clicks
`#store-search-clear` (app.js:3857-3864). Clear empties results, sets
`data-mode="hero"` and focuses the field (app.js:3846-3855).

the results face is blank apart from the status line.

## Open questions / findings for the caller

1. **store.js:217-283 — `paintCsrinLine` swallowed the rest of `paintMeta`.** The closing
   brace of `paintMeta` is at store.js:209, and everything from "The publisher's own
   wordmark" (store.js:243) to `paintInstall()` (store.js:282) sits inside
   `paintCsrinLine`, which references `meta`, a variable that is not in scope there.
   Consequences in the current code: for non-Denuvo games `#sd-logo`, `#sd-facts`,
   `#sd-about`, `#sd-tags`, the screenshot strip, the slideshow and the trailer are
   **never painted**; for Denuvo games it returns early or throws a ReferenceError at
   store.js:245. Only the title, tagline, kicker, size, depots and the bar get filled.
   The hooks above are documented from the templates; they cannot be checked visually in
   the running app until this is fixed (JS change, outside this task).
2. `filterVisible` (app.js:3822-3834) only looks at `.result-card`; in the normal store
   view (`.sf-card`/`.sf-lead`) typing filters nothing and the status reads
   `0 of N shown`. Is `.filtered-out` expected to apply to `.sf-card` in the new design?
3. `.sf-card` and `.sf-lead` are missing from the spatial-navigation list (enhance.js:1033),
   so arrow keys and the gamepad skip the whole front page and the result grid (Tab still
   works because they are `<button>`s).
4. `.typing` / `.shake` are never removed from `#store-search-box`, so once both are
   present the later rule wins (see §2). Should the new CSS combine them, e.g. scope the
   pulse to `.typing:not(.shake)`?
5. `#sd-back` always says "Back to results", including when the page came from the front
   page or the news dialog. Markup copy change?
6. The cinema and the spotlight/lead upscale 460x215 header art to full width; the
   spotlight has no per-slide hook for a transition (only `src` changes). If the design
   wants a crossfade, it needs a markup/JS hook.
7. Unverified: whether some spotlight items resolve to `large_capsule_image` instead of
   the 460x215 header (storeFront.js:78 prefers `header_image`), and the exact size of
   `logo.png` (variable, transparent).
