# DOM hook map — Settings, modal dialogs, tool pages

Scope: `#page-settings`, install locations, destination picker, Steam library picker,
install plan sheet (`#plan`), the shared modal shell (`#modal-overlay`) and every body
app.js generates for it in the ranges listed below, confirm, download auth prompt,
custom-update association, custom game forms, `#page-crack`, `#page-tuning`, the DLSS
Frame Generation card (game flyout) and its updates card (Settings), and the static
blocks of `#page-downloads`.

Sources read in full for this map: `src/index.html` 413-1016, 1132-1150, 1176-1185,
1238-1283; `src/js/app.js` 2295-2313, 2587-2680, 2915-3145, 3148-3418, 3420-3575,
4005-4099, 4993-6738, 6767-6773, 6981-6995, 7040-7042; `src/js/tuning.js`,
`dlssg.js`, `dlssgUpdates.js`, `dialogs.js` (whole); the parts of `enhance.js`
(1449-1573, 1767-1811, 2255-2287, 2561-2628) and `kinetic.js` (60-286) that act on
these elements. Legacy CSS was consulted only to learn which states exist.

Notation:
- `[S]` static markup in index.html; `[G]` generated by JS (file:line of the template).
- `tag#id.class1.class2[attr=value]`, written exactly as in source. A class written
  `.foo?` is conditional.
- "JS sets" lists every mutation the code makes at runtime.

## 2. Settings — row and control kinds

Every control in `#page-settings` is one of the patterns below. §2.12 lists which
section holds which ids.

### 2.1 Section shell
```
div.settings-section[data-sec="…"](#settings-graphics on Graphics)
  h3.settings-title
  p.text-dim[style="font-size:13px;margin-bottom:12px"]   (intro, optional, can contain <b>)
  …rows…
```
`.settings-section` also takes `.flash-target` (§1). The same `.settings-panel`,
`.settings-section` and `.settings-title` classes are reused, without `data-sec`,
on `#page-crack` and `#page-tuning`.

### 2.2 Labelled field — `.form-group`
```
div.form-group
  label                      (bare <label>, no class, no for= except in §2.10)
  input.form-input[type=text|password|number] | select.form-input
  div.setting-hint[style="margin-left:0"]  |  div.text-dim[style="font-size:12px;margin-top:6px"] (may contain a.settings-link)
```
- `.form-group label` must render as a block caption above the field.
- `.form-input` covers text, password and number inputs and `select` elements.
- `.setting-hint` carries a legacy indent (`margin: -2px 0 8px 48px`) so that hints
  line up under the text of a toggle. Inside form groups the markup cancels it with
  `style="margin-left:0"`. Either keep the 48 px indent as the default or drop it
  everywhere; the inline `margin-left:0` is harmless in both cases.

### 2.3 Toggle row — `.toggle-row`
```
label.toggle-row[style?]
  input[type=checkbox]#chk-…        (must be visually hidden; legacy used display:none)
  span.toggle-slider                (the switch track; knob via ::after)
  span                              (caption text, no class)
div.setting-hint                    (optional sibling right after the row)
```
- The state is `input:checked + .toggle-slider`. The JS only sets `.checked`.
- enhance.js:2266-2271 (tour) spotlights `.toggle-row` because the checkbox
  "measures 0×0". The checkbox must have no layout box. `display:none` works, and
  so does a visually-hidden 0×0 pattern, but keyboard focus then needs
  `.toggle-row:focus-within` styling if the input stays focusable.
- Some rows carry an inline `style="margin-top:8px"` (`#chk-ask-destination`) or
  `margin-top:4px` (destination picker).

### 2.4 Color picker row — `.color-pick-row`
```
div.form-group
  label
  div.color-pick-row
    input[type=color].color-pick#inp-accent|#inp-bg|#inp-bp-accent[aria-label]
    span.color-hex.font-mono#accent-hex|#bg-hex|#bp-accent-hex
    button.xbox-btn.xbox-btn-secondary.btn-sm#btn-reset-accent|#btn-reset-bg|#btn-reset-bp-accent
```
JS writes `.value` and `textContent` live on `input` (app.js:5314, 5333-5334).
**`.color-pick-row` is also reused as a generic "horizontal row, centred, gap"
container**: crack page browse row (index.html:548), custom game form rows
(app.js:6143, 6155, 6163, 6171) and the collection modal (app.js:802). It must not
assume a colour input.

### 2.5 Segmented control — `.seg` (Settings, Big Picture layout)
```
div.seg#seg-bp-layout
  button[data-bp-layout="horizontal"].active   "Horizontal shelf"
  button[data-bp-layout="grid"]                "Grid"
```
- The state is `.active` on exactly one button (app.js:5068, 5305-5306). There is no
  ARIA state and no `type`. Not to be confused with `.tn-seg` (§11), which uses
  `aria-checked` and `.is-on`.

### 2.6 Range row — `.range-row`
```
div.form-group.range-row#row-sound-volume
  label[style="margin:0;flex-shrink:0"]  "Volume"
  input[type=range]#inp-sound-volume[min=0][max=1][step=0.05]   (no class)
  output#out-sound-volume                "35%"
```
- JS sets `#row-sound-volume.style.display` to `''` or `'none'`, following
  `#chk-ui-sounds` (app.js:5029, 5162). Do not put `display` with `!important` on
  `#row-sound-volume`, or the inline `none` stops working.
- Expected layout: one horizontal line (label, slider that fills, value on the
  right).

### 2.7 Folder row — `.csrin-dir-row` (used twice)
```
div.csrin-dir-row
  span.font-mono.text-dim#steammanifest-dir-label|#csrin-dir-label[title]   (path; JS sets text + title)
  button.xbox-btn.xbox-btn-secondary.btn-sm#btn-steammanifest-browse|#btn-csrin-browse   "📂 Choose"
  button.xbox-btn.xbox-btn-secondary.btn-sm#btn-steammanifest-dir-reset|#btn-csrin-dir-reset   "Reset"
```
The path span must shrink and ellipsize (legacy: flex row, path `flex:1; min-width:0;
overflow:hidden; text-overflow:ellipsis`, buttons `flex-shrink:0`). Its `title`
attribute holds the full path.

### 2.8 Secret inputs and their generated "Clear saved" button
For `#inp-api-key`, `#inp-steam-web-key`, `#inp-steam-password`,
`#inp-csrin-password` (app.js:5133-5140):
```
input.form-input#…            ← JS forces type="password", autocomplete="off"
[G] button.xbox-btn.xbox-btn-sm[type=button]  "Clear saved"   ← inserted immediately AFTER the input
```
- **The class is `xbox-btn-sm`, not `btn-sm`.** Legacy CSS has no rule for
  `.xbox-btn-sm`, so this button rendered as a full-size `.xbox-btn` with neither
  primary nor secondary styling. The new sheet should define `.xbox-btn-sm` (small
  button, neutral variant).
- The input and the button are siblings inside `.form-group`, followed by the hint
  `div`. Expect the button to wrap below the full-width input unless a layout puts
  them side by side.
- `input[data-clear="true"]` is set while clearing and deleted after save (no visual
  meaning). JS changes `placeholder` to `'Saved securely — enter to replace'` or
  `'Not configured'`.

### 2.9 Inline link — `a.settings-link`
`a#link-get-api-key.settings-link`, `a#link-get-steam-key.settings-link`, placed
inside `div.text-dim`. Accent-coloured inline link.

### 2.10 Bare checkbox row — `.setting-row` (one instance)
```
div.setting-row                                  index.html:921
  label.setting-label[for="chk-adaptive"]  "Adaptive speed"
  input[type=checkbox]#chk-adaptive[checked]    ← NOT inside .toggle-row: a raw checkbox

Legacy CSS gave `.setting-row` only a transition and `.setting-label` nothing, so
this rendered as a native checkbox. **Decision needed**: style `.setting-row` as a
toggle (the checkbox has no `.toggle-slider` sibling, so it needs
`appearance:none` styling on the input itself), or change the markup to the
`.toggle-row` pattern. Only `.checked` is read and written by the JS.

Host in Settings: `[S] div#install-locations` (index.html:794). Host in the picker:

```

      div.loc-radio                                    (empty radio dot; filled when .is-default)

        div.loc-path                                   (full path text)

Template (app.js:5365-5374):
```js
<div class="loc-row${loc.isDefault ? ' is-default' : ''}${tooSmall ? ' too-small' : ''}${loc.exists ? '' : ' missing'}" data-path="${esc(loc.path)}" role="button" tabindex="0">

  </div>

```
- States:
  - `.is-default` marks the default folder in Settings and the selected folder in
    the picker. The picker moves it on click (app.js:5482-5483, 5520).
  - `.too-small`: free space is below the required bytes (picker only). Colours
    the meta `<b>` and the bar.
  - `.missing`: the folder does not exist (legacy dimmed the row).
- Inline style: `i` width in `%` (0-100, one decimal).
- Empty state: `[G] div.empty-state-small` with the text "No install folders yet. Add
  one below — it becomes the default for new downloads." (app.js:5384), or "No
  install folders found. Browse for one below." in the picker (app.js:5460).
- Behaviour: the whole row is clickable and keyboard-activatable (Enter / Space);
  `.loc-remove` stops propagation. The row is a gamepad focus target (§0), so it
  needs a `:focus` style. Expected layout: horizontal (radio | info flex:1
  min-width:0 | remove/tag), with the path ellipsized or wrapped.

## 21. Pitfalls found in the current code and legacy CSS (facts, for the rewrite)

1. `#drop-zone.dragover` in legacy kinetic.css never matches; the JS class is `drag-over`.
2. `xbox-btn-sm` (two uses) and `xbox-input` (one use) had no styling.
3. `.setting-row` / `.setting-label` had no layout; `#chk-adaptive` is a native checkbox.
4. `#crack-scan-results` keeps `.empty-state-small` while showing results.
5. `#plan-legend` holds only text; `#plan-legend > *` selectors match nothing.
6. `#speed-chart` / `#dl-focus-chart` grow without bound on HiDPI unless CSS sizes them.
7. `#tn-spark` draws at a fixed 72-px height; a different CSS height stretches it.
8. `#tn-status` has its className overwritten.
9. `.queue-card` is in the gamepad focus list but has no tabindex.
10. `#dl-disk-speed` / `.dl-disk-sep` are never re-hidden after the first job that reports disk speed.
11. The confirm modal's danger state is an inline `color:var(--accent-red)` on the primary button.
